# 一句话游戏 - 开发指南与常见问题

## 开发环境搭建

### 1. 环境要求
- Node.js >= 16.x
- npm >= 8.x

### 2. 安装依赖
```bash
cd youxijia
npm install
```

### 3. 配置环境变量
```bash
# 复制示例配置文件
copy .env.example .env

# 编辑 .env 文件，填写必要配置
# LLM_API_KEY=你的API密钥
# LLM_BASE_URL=API地址
# LLM_MODEL=默认模型
# ADMIN_PASSWORD=管理后台密码
```

### 4. 启动服务
```bash
# 开发模式
node server.js

# 或使用 Windows 批处理
start.bat

# 停止服务
stop.bat
```

服务默认运行在 `http://localhost:3000`

## 开发工作流

### 前端开发

1. **源文件位置**: `src/js/app.js`
2. **开发时**: 服务器直接使用 `src/js/app.js`（未混淆版本）
3. **生产构建**: 运行 `node build.js` 生成混淆后的 `public/js/app.js`

### 后端开发

直接修改 `server.js`，重启服务即可生效。

### 样式修改

直接修改 `public/css/style.css`，刷新页面即可。

### 数据库

- SQLite数据库文件：`games.db`
- 数据库在首次启动时自动创建
- 表结构在 `server.js` 的 `initDatabase()` 函数中定义

## 代码规范

### JavaScript
- 使用驼峰命名法
- 函数名使用动词开头（如 `loadGames`, `showDetail`）
- 异步函数使用 `async/await`
- 使用 `const` 和 `let`，避免 `var`

### API设计
- RESTful风格
- 统一响应格式 `{ success, data, error }`
- 使用HTTP状态码表示结果

### 命名约定
- API路由：`/api/资源名`（复数）
- 前端函数：`动词+名词`（如 `loadMyGames`）
- CSS类名：`组件-元素-修饰符`（如 `game-card-title`）

## 关键功能实现

### Token认证机制

项目使用Token机制识别用户，user-token 和 author-token 通常是相同的值：

```javascript
// 获取或生成设备指纹作为Token
function getUserToken() {
  let token = localStorage.getItem('aigame-user-token');
  if (!token) {
    token = localStorage.getItem('aigame-author-token');
  }
  if (!token) {
    token = localStorage.getItem('user_token'); // 兼容旧版
  }
  if (!token) {
    token = generateDeviceFingerprint();
    saveUserToken(token);
  }
  return token;
}

function saveUserToken(token) {
  localStorage.setItem('aigame-user-token', token);
  localStorage.setItem('aigame-author-token', token);
}
```

**注意**: 在 `games.html` 等独立页面中，需要确保Token读取逻辑一致。

### 游戏生成流程

```
1. 用户输入提示词
2. 前端检查积分/试玩额度
3. 调用 POST /api/generate 或 /api/trial/generate
4. 后端验证用户权限
5. 调用 AI API 生成游戏代码
6. 从返回的代码中提取元信息（标题、描述等）
7. 保存到数据库
8. 生成静态HTML文件到 /g/{xx}/{id}.html
9. 返回游戏信息给前端
10. 前端显示保存确认界面
```

### 游戏编辑流程

```
1. 用户点击"编辑"按钮
2. 前端验证是否为游戏作者
3. 打开游戏编辑器页面
4. 显示当前代码预览和AI建议
5. 用户输入修改需求
6. 调用 POST /api/games/:id/edit
7. AI返回修改后的代码
8. 前端更新预览
9. 用户选择保存方式（覆盖/另存为新游戏）
```

### 路由与导航

从子页面返回主页特定标签：

```javascript
// games.html 中设置返回链接
if (source === 'my-games' || source === 'my-likes' || source === 'my-favorites') {
  backLink.href = '/?tab=profile';
}

// index.html 中处理路由
function handleRouting() {
  const params = new URLSearchParams(window.location.search);
  const tab = params.get('tab');
  if (tab === 'profile') {
    directSwitchToTab('profile');  // 使用无动画切换避免闪烁
  }
}
```

## 常见问题与解决方案

### Q1: 数据不显示（"共 0 个游戏"）

**原因**: Token不一致导致API无法识别用户

**解决**: 确保不同页面使用相同的LocalStorage键名读取Token

```javascript
// 错误示例
localStorage.getItem('userToken')  // games.html使用

// 正确示例  
localStorage.getItem('aigame-user-token')  // 与app.js一致
```

### Q2: 返回按钮导航错误

**原因**: 返回链接硬编码为 `/`

**解决**: 根据来源动态设置返回地址

```javascript
const backLink = document.querySelector('.back-link');
if (source.startsWith('my-')) {
  backLink.href = '/?tab=profile';
} else {
  backLink.href = '/';
}
```

### Q3: 页面切换时闪烁

**原因**: 使用带动画的切换函数，且执行顺序不当

**解决**: 
1. 创建无动画的直接切换函数
2. 在 `DOMContentLoaded` 中先处理路由，再初始化其他模块

```javascript
document.addEventListener('DOMContentLoaded', () => {
  handleRouting();     // 先处理路由
  initMainTabs();      // 再初始化UI
  loadInitialData();   // 最后加载数据
});
```

### Q4: 游戏详情页无法点赞

**原因**: `x-user-token` 请求头未正确设置

**解决**: 确保API请求包含正确的Header

```javascript
fetch(`/api/games/${gameId}/like`, {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'x-user-token': getUserToken()
  }
});
```

### Q5: 开发环境与生产环境表现不一致

**原因**: 生产环境使用混淆后的代码

**解决**: 
1. 确保修改的是 `src/js/app.js`
2. 每次部署前运行 `node build.js`
3. 检查 `server.js` 中的静态文件配置

### Q6: 数据库被锁定

**原因**: SQLite并发写入冲突

**解决**:
1. 确保只有一个服务器实例在运行
2. 使用 `better-sqlite3` 的同步API避免冲突
3. 运行 `stop.bat` 停止所有实例后重新启动

### Q7: 游戏生成失败

**可能原因**:
- API Key无效或额度不足
- 网络连接问题
- 模型不可用

**解决**:
1. 检查 `.env` 中的 `LLM_API_KEY` 配置
2. 尝试切换到其他模型
3. 查看服务器日志获取详细错误信息

### Q8: 游戏静态文件丢失

**原因**: 数据库记录存在但HTML文件被删除

**解决**:
1. 运行 `node repair-game.js` 修复
2. 或在管理后台使用"修复"功能
3. 使用 `scripts/regenerate-static-games.js` 批量重生成

### Q9: 积分显示不正确

**原因**: LocalStorage缓存与服务器数据不同步

**解决**:
1. 刷新页面触发重新获取
2. 清除 `aigame-credits` LocalStorage项
3. 调用 `loadCredits()` 函数

### Q10: 评论无法提交

**可能原因**:
- 用户被封禁
- 内容包含敏感词
- 请求频率过高

**解决**:
1. 检查用户封禁状态
2. 检查服务器日志
3. 等待一段时间后重试

## 调试技巧

### 1. 查看数据库内容

```bash
# 安装sqlite3命令行工具，或使用DB Browser for SQLite
sqlite3 games.db

# 查看表结构
.schema games

# 查看数据
SELECT id, title, status FROM games LIMIT 10;

# 查看用户
SELECT account_id, nickname, created_at FROM user_accounts LIMIT 10;
```

### 2. API调试

```bash
# 使用curl测试API
curl http://localhost:3000/api/games?limit=5

# 带Token的请求
curl -H "x-user-token: your_token" http://localhost:3000/api/my-likes

# POST请求
curl -X POST -H "Content-Type: application/json" \
  -H "x-user-token: your_token" \
  -d '{"prompt":"做一个贪吃蛇"}' \
  http://localhost:3000/api/generate
```

### 3. 前端调试

在浏览器控制台中：
```javascript
// 查看当前Token
console.log(localStorage.getItem('aigame-user-token'));
console.log(localStorage.getItem('aigame-author-token'));

// 查看积分
console.log(localStorage.getItem('aigame-credits'));

// 手动触发函数（开发环境，未混淆）
loadMyGames();
openGame('game_id');
loadCredits();

// 清除本地数据（谨慎使用）
localStorage.clear();
```

### 4. 日志查看

服务器日志会输出到控制台，包括：
- API请求日志
- 错误信息
- AI生成进度
- 数据库操作

### 5. 网络请求调试

使用浏览器开发者工具的Network面板：
- 查看请求/响应详情
- 检查请求头（特别是Token）
- 查看响应数据

## 扩展开发建议

### 添加新API

1. 在 `server.js` 中添加路由
2. 在 `src/js/app.js` 中添加调用函数
3. 更新 `doc/03-API接口文档.md`

### 添加新页面

1. 在 `public/` 下创建HTML文件
2. 确保Token读取逻辑与主应用一致
3. 复用 `style.css` 样式
4. 添加必要的JS逻辑

### 修改数据库结构

1. 在 `server.js` 的数据库初始化部分修改表结构
2. 添加数据迁移逻辑（使用 ALTER TABLE）
3. 更新 `doc/02-数据库架构.md`
4. 测试现有数据兼容性

### 添加新的AI模型

1. 在 `server.js` 的模型配置中添加
2. 确保API格式兼容（OpenAI格式）
3. 在管理后台配置模型参数
4. 测试生成效果

### 修改UI主题

1. 修改 `public/css/style.css` 中的CSS变量
2. 保持赛博朋克风格的配色协调
3. 测试在不同设备上的显示效果

## 性能优化建议

1. **数据库优化**: 定期运行 VACUUM 命令
2. **静态文件**: 使用CDN加速
3. **API缓存**: 对不常变化的数据添加缓存
4. **图片优化**: 压缩图片资源
5. **代码分割**: 考虑将大型JS文件拆分

---

## 安全注意事项

1. **API Key**: 不要在前端代码中暴露
2. **管理员密码**: 使用强密码
3. **用户输入**: 始终进行转义和验证
4. **SQL注入**: 使用参数化查询
5. **XSS防护**: 输出时进行HTML转义
6. **CORS配置**: 限制允许的域名
